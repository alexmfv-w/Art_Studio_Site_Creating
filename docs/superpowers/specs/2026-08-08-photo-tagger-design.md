# Тэггер фотографий — дизайн

Дата: 2026-08-08
Статус: одобрено заказчиком в диалоге, готово как основа для плана реализации

## Контекст и задача

Спека визуального пересмотра (`2026-08-08-visual-redesign-direction.md`) зафиксировала главное ограничение: на сайте нет ни одной реальной фотографии, и исследование показало, что именно фотографии несут материальность у всех аналогов. Выяснилось, что фотографии у студии есть — их много, и их нужно разметить, чтобы было понятно, какую куда ставить.

Нужен минимальный локальный инструмент: пролистывать фотографии из папки по одной, писать к каждой короткое описание, сохранять результат в файл, с которым потом удобно работать при вёрстке страниц.

**Явно вне рамок:** загрузка/редактирование фотографий, оптимизация и ресайз для веба, привязка фото к конкретным страницам сайта, любая база данных.

## Решения

### Формат хранения — TSV

`photos.tsv` в папке с фотографиями. Колонки, разделённые табом:

```
file	description	tags	width	height	orientation
IMG_001.jpg	руки за гончарным кругом	дети;керамика;процесс/руки	4032	3024	landscape
IMG_002.jpg	готовая ваза, синяя глазурь	керамика;готовая работа	3024	4032	portrait
```

Теги внутри колонки разделяются точкой с запятой.

Обоснование: заказчик просил «табличку либо текстовый файлик» — TSV одновременно и то, и другое (открывается как таблица в Excel/Numbers, читается как обычный текст). Таб выбран разделителем вместо запятой, потому что описания на русском заведомо содержат запятые и тире, а табы — нет. При сохранении табы и переводы строк в описании заменяются пробелом, чтобы формат не мог сломаться.

### Свободное описание плюс теги

Описание пишется свободным текстом. Дополнительно — кнопки-теги в один клик, множественный выбор (одному фото можно поставить несколько тегов). Теги необязательны: фотографию можно разметить одним описанием.

Список тегов согласован с заказчиком; каждый тег влияет на конкретное решение при вёрстке, декоративных нет:

- **Аудитория** — `взрослые`, `дети`, `подростки`, `общее`. Определяет, на какую страницу фото вообще допустимо ставить.
- **Направление** — `живопись`, `рисунок`, `каллиграфия пером`, `каллиграфия брашпеном`, `керамика`, `лепка/пластилинография`, `скетчинг`, `леттеринг`, `роспись`. Ложится на карточки направлений.
- **Что в кадре** — `процесс/руки`, `готовая работа`, `мастерская`, `преподаватель`, `ученики`, `материалы/инструменты`. Самая ценная группа: по итогам исследования материальность несут кадры процесса и рук — они идут в герой и интро, готовые работы — в витрину и карточки.
- **Пометки** — `★ на главную`, `не публиковать`.

Тег «лица видны» обсуждался (публикация изображения человека требует согласия по 152.1 ГК РФ, для детей — родительского), но по подтверждению заказчика разрешения получены на все фотографии, поэтому в списке его нет.

Теги группируются только в интерфейсе. В файле это плоский список — так можно добавить тег, не меняя формат.

### Автоматические поля

`width`, `height`, `orientation` (`landscape` / `portrait` / `square`) вычисляются программой, заказчик их не вводит. Нужны при вёрстке: по ним видно, какое фото годится в широкий блок на всю ширину, а какое — только в узкую колонку.

Размеры читаются напрямую из заголовков файлов (JPEG SOF-маркеры, сигнатура PNG) — **без Pillow и любых других зависимостей**, только стандартная библиотека Python. На машине Python 3.9.6 и Pillow не установлен; ставить зависимость ради двух чисел избыточно.

### Запуск

```
python3 tools/photo-tagger.py ~/Pictures/kistpero
```

Путь к папке — обязательный аргумент (заказчик просил возможность указывать папку). Скрипт поднимает локальный HTTP-сервер и открывает браузер на нужной странице.

Фотографии живут **вне репозитория** — они тяжёлые и не должны попадать в git. В репозиторий позже копируется только `photos.tsv`.

### Интерфейс

Одна страница: фотография крупно, под ней поле описания, ряды кнопок-тегов по группам, кнопки «назад»/«вперёд» и счётчик вида «12 / 340». Тег переключается кликом, активный визуально выделен. Описание и теги сохраняются автоматически при переходе к соседней фотографии — отдельной кнопки «сохранить» нет. Стрелки клавиатуры дублируют кнопки навигации.

### Возобновляемость

При запуске существующий `photos.tsv` читается, и уже введённые описания и теги подставляются. Разметку можно делать в несколько заходов. Файл, сохранённый ранней версией инструмента (без колонки `tags`), читается без ошибок — теги у таких строк просто пустые.

## Архитектура

Один файл `tools/photo-tagger.py`, стандартная библиотека (`http.server`, `json`, `csv`, `webbrowser`, `pathlib`). Внутри три ответственности с чёткими границами:

- **Чтение размеров изображения** — чистая функция `image_size(path) -> (width, height) | None`, парсит байты заголовка. Тестируется без сети и без сервера.
- **Хранилище TSV** — функции `load_entries(tsv_path) -> Dict[str, Dict[str, str]]` (описание и теги по имени файла) и `save_rows(tsv_path, rows)`. Тоже чистые, тестируются на временных файлах.
- **HTTP-слой** — отдаёт HTML-страницу, файлы фотографий и принимает POST с описанием. Единственное место, где есть ввод-вывод по сети.

HTML/CSS/JS страницы встроены в тот же файл строкой — инструмент одноразовый и вспомогательный, разносить его по файлам не нужно.

## Как проверяется

Автотесты для двух чистых частей (размеры изображений, чтение/запись TSV) через `unittest` из стандартной библиотеки — раннера в проекте нет, но для отдельного Python-скрипта `python3 -m unittest` доступен всегда. HTTP-слой проверяется вручную: запустить на тестовой папке с парой картинок, пролистать, убедиться, что TSV записался и подхватился при перезапуске.

## Самопроверка

- **Плейсхолдеры:** нет, все решения конкретны.
- **Согласованность:** формат TSV, отсутствие тегов и указание папки аргументом — прямые решения заказчика из диалога; автоматические поля не требуют его участия и не противоречат «минимальности».
- **Масштаб:** один файл, один сценарий использования, вспомогательный инструмент вне сайта. Декомпозиция не нужна.
