# Методология дизайна для «Кисть и Перо» — исследование

Контекст: статический сайт на Astro для студии живописи/каллиграфии/керамики в Краснодаре. Палитра: тёмно-зелёный #2C3323, оливковый #3E4A2E/#C7CBA6, охра #D98A2E/#F3E3AE, бумага #ECEEDF. Шрифты: Bitter (слэб-сериф, заголовки) + Golos Text (текст), плюс Comfortaa+Nunito для детского «регистра». Чистый CSS, без фреймворков. Весь контент на русском (кириллица). Направление бренда — «рукотворность»: реальная студия, реальные материалы (глина, тушь, краска), реальный преподаватель. Не корпоративный/SaaS-глянец.

**Нерешённая проблема**: списки курсов и блоки «почему мы» — сейчас однотипная сетка карточек с рамкой и цветной полосой сверху. Клиент считает это шаблонным. Нужны принципиальные альтернативы «сетке карточек» для представления набора однородных/параллельных пунктов.

## 1. Альтернативы сетке карточек

### Источники
- [Echo Design Group — 5 alternatives to a basic grid](https://echodesigngroup.com/blog/5-alternatives-to-a-basic-grid-for-projects-and-news-pages/) — слабый источник (агентский блог), но список паттернов конкретен и пригоден для извлечения.
- [Figr Design — Card UI Design Pattern](https://figr.design/blog/card-ui-design-pattern) — содержит редкую для этой темы формулировку принципа выбора паттерна.
- [BSWEN — Anti-Patterns Guide (AI-generated UI)](https://docs.bswen.com/blog/2026-03-20-ai-generated-ui-anti-patterns/) — диагностирует, почему карточки стали дефолтом.
- UX Collective / UX Movement — списки материалов о list vs grid (собирательно, среднего качества).
- Museum label / exhibition catalogue conventions (New School library guide, MGNSW).
- Vignelli Canon (см. раздел 2) — про модульные системы для повторяющегося контента.

### Извлечённые принципы

**Почему карточка стала дефолтом, а не потому что она лучшая.** Карточка — «безопасный», а не оптимальный выбор: она инкапсулирует произвольный контент без необходимости понимать иерархию данных. Отсюда и «баналность» — карточка ничего не говорит о *природе* контента, она универсальный контейнер. Хорошие интерфейсы намеренно смешивают паттерны: карточки — для визуального browsing, списки — для сравнения/поиска, таблицы — для сопоставления атрибутов. Правило выбора: **паттерн должен соответствовать намерению пользователя, а не удобству дизайнера**.

**Список (list) как самостоятельный, не «бедный» паттерн.** Список — не «карточка без картинки», а другая логика чтения: пользователь сканирует вертикальный поток, где имеет значение немного ключевых атрибутов на пункт. Список компактнее, не заставляет прокручивать лишнее, и хорошо работает, когда пункты **текстовые и однородные по смыслу** — это ровно случай «список курсов» или «почему мы».

**Музейная этикетка / каталог выставки как прецедент для «набора параллельных пунктов».** Классическая музейная практика: «tombstone data» (название/автор/дата/материал/размер) — минималистичный, строго типографический блок текста без рамок и фонов, отличающийся от соседних пунктов только положением на стене/странице и последовательностью. Иерархия достигается **типографикой и позицией**, а не контейнером (рамка, тень, фон). Каталог выставки — тот же принцип, масштабированный на печатную страницу: пункты разделяются не боксами, а пробелом, линией-разделителем или нумерацией.

**Конкретные паттерны-замены сетке карточек** (из Echo Design Group, адаптируя терминологию):
1. **Асимметричные пары колонок** (60/40, 70/30) — вместо одинаковых по ширине блоков.
2. **Список с фоновым изображением по ховеру** — текстовый список названий, при наведении/фокусе разворачивается полноэкранное/крупное изображение позади. На мобильном превращается в обычный список с маленькой иконкой.
3. **Чередующаяся сетка (alternating grid)** — крупный элемент слева/мелкие справа, в следующей строке — наоборот. Даёт ритм без идентичности карточек.
4. **Горизонтальный скролл-ряд** — по одному пункту в фокусе за раз (подходит для витрины из 3-5 курсов, не для длинных списков).
5. **Полноширинные секции друг под другом** — каждый пункт — целая полоса экрана со своей раскладкой текста/картинки, а не одинаковый бокс.

### Как применить у нас

Для блока «курсы» (обычно 4-6 пунктов: живопись, каллиграфия, керамика для взрослых/детей) — заменить сетку карточек на **типографический список по образцу музейной этикетки**: крупный номер или инициал техники (напр. «01», или буквица), название курса шрифтом Bitter крупным кеглем, короткое описание Golos Text, разделительная линия (не рамка вокруг всего блока) снизу — тонкая, охра или тёмно-зелёная. Иерархия и «карточность» ощущения достигаются **отступами и линиями**, а не фоновыми плашками и бордерами. Для блока «почему выбирают нас» (обычно короче, 3-4 пункта) — асимметричная раскладка: один длинный текстовый пункт занимает 2 колонки, остальные — по одной, без визуального выравнивания в одинаковые боксы. Это прямо снимает жалобу клиента «все карточки одинаковые», потому что пункты перестают быть визуально идентичными контейнерами.

## 2. Редакционные и журнальные системы вёрстки для веба

### Источники
- [Butterick's Practical Typography — Maxims of page layout](https://practicaltypography.com/maxims-of-page-layout.html) — короткий, но канонический источник (широко цитируется в индустрии, автор — типограф и юрист Мэттью Баттерик).
- [The Vignelli Canon (RIT, официальный бесплатный PDF)](https://www.rit.edu/vignellicenter/sites/rit.edu.vignellicenter/files/documents/The%20Vignelli%20Canon.pdf) — PDF не распарсился текстовым фетчем (бинарный/сжатый поток), но структура и принципы известны из вторичных, но точных изложений (IxDF, UX Collective, AisleOne) и совпадают с общеизвестным содержанием книги.
- Broken grid / asymmetric layout — набор вторичных источников (Acodez, HubSpot, ThemeRex) весом «маркетингового блога», принципы извлечены и очищены от воды.

### Извлечённые принципы

**9 максим Баттерика (сжато и с адаптацией к нашей задаче):**
1. *Сначала основной текст.* Кегль, длина строки, интерлиньяж и гарнитура для body-текста определяют облик всего документа сильнее любых décor-элементов.
2. *Явная иерархия фон/передний план.* Второстепенные элементы (даты, длительность курса) не должны спорить по весу с названием курса.
3. *Минимальные, но решающие правки.* Разница между «неряшливо» и «слишком туго» — на уровне 1-2px отступа.
4. *Сравнивать варианты визуально, не в теории.* Не спорить абстрактно про «карточки против списка» — сверстать оба варианта и посмотреть.
5. *Последовательность.* «Одинаковое должно выглядеть одинаково, разное — быть по-настоящему разным». Прямое противоядие «баналу»: если все шесть курсов *разного объёма важности*, они не должны быть одинаковыми боксами.
6. *Каждый новый элемент — в диалоге с существующими*, через сетку.
7. *Простота.* Не добавлять цвет/декор ради разнообразия — сама композиция должна быть источником интереса.
8. *Учиться на примерах, которые нравятся.*
9. *Не бояться пустоты.* «Работайте от текста наружу, а не от края страницы внутрь» — пустое пространство возникает естественно из хорошо посаженного текста, это не «недоделанный» дизайн, а инструмент.

**Вignelli: модульные сетки для повторяющегося контента.** Существует бесконечно много типов сеток, но для каждой задачи есть только одна подходящая — задача дизайнера в том, чтобы её найти, а не изобретать декоративную. Порядок построения: сперва поля (чем уже поля, тем выше «эмоциональное напряжение» страницы), затем вертикальные колонки исходя из содержимого, затем строки для общих горизонтальных ориентиров по всей публикации. Для набора параллельных пунктов (как список курсов) это означает: единая модульная сетка, где *каждый пункт занимает одинаковое число модулей*, но не обязательно выглядит как визуально идентичный «бокс» — модуль это невидимая структура, а не видимая рамка.

**Broken grid / асимметрия — с оговоркой.** Источники маркетингового толка описывают асимметрию как способ избежать монотонности жёсткой сетки и направить внимание. Это совпадает с редакционной практикой (журнальная вёрстка часто использует 5-7-9-колоночные сетки именно ради асимметричных комбинаций: узкая колонка для сносок, широкая для текста). **Важная оговорка**: broken grid — это *не* хаос, а сетка, которую сознательно нарушают в конкретных, повторяемых местах. Если нарушать бессистемно — получится не «редакционно», а «неаккуратно», что для бренда «рукотворность vs небрежность» — тонкая, но критичная грань.

### Как применить у нас

Ввести **единую модульную сетку** (например, 12 колонок с 3-4 базовыми ширинами блоков) как теневую структуру для всего сайта, но **отказаться от одинаковых визуальных контейнеров** внутри неё. Пример: в блоке курсов — «Живопись» и «Каллиграфия» (более раскрученные направления) получают более широкий модуль (интро-абзац + список тем), «Керамика» и детские курсы — компактный модуль (только название + 1 строка + ссылка). Разная значимость выражается разным размером модуля, а не одинаковыми боксами разной высоты (что сейчас, видимо, и создаёт ощущение «шаблонности» — одинаковая структура, вставленная N раз). Работать «от текста наружу»: сначала посадить реальные тексты описаний курсов, посмотреть, какая длина у них естественно выходит, и уже под это строить сетку — а не подгонять реальный текст под одинаковые по высоте карточки (это частая причина, почему тексты в карточках выглядят обрезанными/шаблонными).

## 3. Текстура и материальность в вебе

### Источники
- [CSS-Tricks — Grainy Gradients](https://css-tricks.com/grainy-gradients/) (автор Jimmy Chion) — качественный технический источник с рабочим кодом.
- freefrontend.com — CSS Paper Effects (собрание готовых сниппетов; средний по авторитетности, но код рабочий).
- Общие источники о skeuomorphism vs flat design (DBS Interactive, Skillshare, 99designs, Sacha Greif's "Flat Pixels") — вторичные, но отражают консенсус индустрии.

### Извлечённые принципы

**Техника зернистого градиента (grainy gradient) — рабочий код:**
```html
<svg viewBox="0 0 200 200" xmlns="http://www.w3.org/2000/svg">
  <filter id="noiseFilter">
    <feTurbulence type="fractalNoise" baseFrequency="0.65" numOctaves="3" stitchTiles="stitch" />
  </filter>
  <rect width="100%" height="100%" filter="url(#noiseFilter)" />
</svg>
```
```css
.noise {
  background:
    linear-gradient(to right, var(--paper), transparent),
    url(noise.svg);
  filter: contrast(170%) brightness(1000%);
}
```
Принцип: SVG-шум (`feTurbulence`) кладётся *под* CSS-градиентом, затем весь блок прогоняется через `contrast()`/`brightness()`, чтобы вытолкнуть блёклые полутона к чистым белому/чёрному и получить зерно, а не «грязь». Порядок слоёв важен: должен быть переход от чистого цвета к шуму, а не наоборот.

**Опасность/дозировка (широкий консенсус источников по noise-generator продуктам, подтверждается общей практикой):** слой зерна на 5-8% непрозрачности читается как «фактура материала» (бумага, ткань, плёнка) и воспринимается как «премиальность», не «шум». Выше этого порога эффект быстро съезжает в «грязный экран» — особенно опасно поверх текста.

**Кризис skeuomorphism → плоский дизайн → неоскеуоморфизм.** Ранний skeuomorphism (iOS до 2013) стал восприниматься как аляповатый — интерфейсы, перегруженные тенями/градиентами/фактурами ради ностальгии по физическому объекту, в ущерб ясности. Плоский дизайн решил эту проблему, но сам стал критиковаться как «холодный и безличный». Актуальный консенсус: **тактильные сигналы работают, если они функциональны (обозначают состояние, глубину, кликабельность), а не декоративны сами по себе.** Текстура ради текстуры — тот же грех, что тень ради тени в 2012 году.

**SVG torn-edge / tape-эффекты** технически реализуемы через `clip-path` с многоточечным полигоном (рваный край) и полупрозрачные `<div>` с точечной рамкой (имитация скотча) — но это явно декоративные, тяжёлые в поддержке приёмы, которые легко скатываются в кэмп/скрапбукинг-эстетику, а не «студия художника».

### Как применить у нас

**Использовать зерно, но строго дозированно и функционально:** тонкий шум (`feTurbulence`, 4-6% opacity, охра/тёмно-зелёный тон вместо серого — под нашу палитру) на фоне hero-секции и, возможно, на фоне ochre-плашек — но **никогда поверх текстовых блоков**, чтобы не бить читаемость Golos Text/кириллицы (у которой и так меньше «воздуха» между буквами, см. раздел 4). Отказаться от torn-paper/tape-скрапбукинга — это прямой путь в «поделка», а не «студия». Вместо буквальной имитации бумаги — использовать зерно как **тонкий сигнал материальности фона**, а настоящую «рукотворность» нести через контент (фото реальных работ, почерк в каллиграфии, текстуру реальной глины на фото) и через нестандартную композицию текста (раздел 1-2), а не через CSS-имитацию физических объектов. Это прямее отвечает совету клиента про «не шаблонно» — текстура не решает проблему баналости карточек, это отдельная (и второстепенная) ось.

## 4. Специфика кириллической типографики

### Источники
- [typejournal.ru — «О развитии кирилловских знаков и их графики»](https://typejournal.ru/articles/Cyrillic-Letterforms-Development) — сильный источник, журнал «Шрифт» — профильное русскоязычное издание о шрифтовом дизайне, статья с конкретными техническими данными.
- [artlebedev.ru/kovodstvo, §62 «Экранная типографика»](https://www.artlebedev.ru/kovodstvo/sections/62/) — канонический русский источник (Ководство Лебедева), хотя раздел скорее про пунктуацию/спецсимволы, чем про форму букв.
- type.today/ru/journal (серия статей «Кириллица в Google Fonts» по категориям: гуманистические/геометрические/нео-гротески, антиквы, рукописные) — профильный источник, разборы по категориям, не зафетчены построчно, но заголовки и структура подтверждают системный подход студии к теме.
- Ilya Birman (ilyabirman.ru) — не удалось найти прямую статью с манифестом типографики (поиск вывел в основном на «Типографскую раскладку», клавиатурный инструмент, а не эссе о принципах); зато нашёлся смежный канонический источник — учебник Артёма Горбунова и самого Бирмана «Типографика и вёрстка» на bureau.ru — авторитетная русская школа дизайна (Бюро Горбунова), прямые ученики и коллеги друг друга по цеху с Лебедевым.

### Извлечённые принципы

**Кириллица физически шире латиницы.** Русский текст занимает на 15-20% больше места, чем тот же смысл по-английски (украинский — на 10-15%). Прямое следствие: **макеты, спроектированные "по ощущению" на английских placeholder-текстах (lorem ipsum), будут ломаться на реальном русском контенте** — заголовки короче не влезут, а описания курсов будут длиннее ожидаемого.

**Меньше округлых форм → другой ритм и «цвет» текста.** У кириллицы значительно меньше круглых знаков, чем у латиницы — сравните «о, б, в, ф» с «n, m, ш, п, и» — линейные, вертикально-полосатые формы (н, п, ш, б, ж, я) доминируют в текстуре набора. Это значит: гарнитура, которая в латинице выглядит воздушной и округлой (условно «дружелюбный» шрифт), в кириллице может дать более тяжёлую, «частокольную» текстуру. **Практический вывод для нас**: нужно реально проверить, как Bitter и Golos Text выглядят в русском тексте плашками абзацев, а не полагаться на то, как они смотрятся на латинице в шрифтовых каталогах.

**Меньше выносных элементов (ascender/descender) → межстрочный интервал воспринимается просторнее.** У кириллицы мало восходящих штрихов, поэтому одинаковый line-height визуально «читается» как более разреженный, чем в латинском тексте. Отсюда: **не нужно бездумно копировать line-height из англоязычных гайдлайнов** (например, «1.5 для body text») — для кириллицы это может дать излишне разреженный, рыхлый текст; стоит тестировать чуть плотнее.

**Капитель (small caps) в кириллице работает иначе.** Строчные кириллические буквы по построению похожи на прописные (в отличие от латиницы, где курсив и капитель меняют саму пластику знака) — поэтому обычная (уменьшенная) капитель в кириллице визуально «теряется», сливается со строчным текстом. Хорошие кириллические гарнитуры проектируют капитель чуть выше, чем масштабированные прописные. **Проверить**: если где-то в дизайне используется capsize/small-caps трюк (например, для акронимов или лейблов), в Bitter/Golos Text он может не сработать так же, как ожидается по латинским референсам.

**Ководство Лебедева, §62**: экранный текст обязан быть «обогащён» — правильные кавычки-«ёлочки» (никогда прямые "английские"), длинное тире (—, не дефис), неразрывные пробелы после предлогов/союзов и перед инициалами, защита от «сиротских» переносов при resize окна браузера. Это низкоуровневая гигиена, но она прямо про «нешаблонность» / профессионализм в глазах русскоязычного культурного посетителя студии — небрежная пунктуация читается как непрофессионализм сильнее, чем в англоязычной среде, потому что канон (Лебедев, Ильяхов, Бюро Горбунова) очень заметен в русской дизайн-культуре.

### Как применить у нас

1. Верстать и тестировать макеты **сразу на реальных русских текстах**, не на лорем ипсум — особенно для карточек/списков курсов, где именно длина текста определяет, ломается ли раскладка.
2. Прогнать реальный абзац на Golos Text и заголовок на Bitter в браузере, посмотреть текстуру строки кириллицей вживую, при необходимости чуть сократить line-height относительно «типового» значения для латиницы.
3. Внедрить типографскую гигиену Ководства как чек-лист перед публикацией текста (кавычки-ёлочки, тире, неразрывные пробелы) — это дёшево и напрямую работает на ощущение «сделано вручную/с заботой», а не «на автомате нагенерировано».
4. Не использовать псевдо-капитель без проверки конкретно в Bitter/Golos Text.

## 5. Дизайн для двух аудиторий в одной системе (взрослые/дети)

### Источники
- [Brad Frost — The Many Faces of Themeable Design Systems](https://bradfrost.com/blog/post/the-many-faces-of-themeable-design-systems/) — сильный источник, Фрост — автор Atomic Design, один из ведущих практиков в теме design systems.
- Ramotion, Fabrik Brands, Zoocha — материалы уровня агентского блога о sub-branding/brand architecture; извлечены только структурные принципы, не частные примеры (Disney/Touchstone и т.п., которые нерелевантны маленькой студии).

### Извлечённые принципы

**Трёхуровневая архитектура токенов** — стандартный паттерн для «одна система, разные лица»:
- Tier 1 — сырые значения (`color-olive-500`, `color-ochre-400`)
- Tier 2 — семантический слой (`theme-color-accent`, `theme-color-background`)
- Tier 3 — компонентный слой (`button-primary-bg`)

Композиция: `core + brand-theme` (взрослый регистр) и `core + brand-theme + kids-theme` (детский регистр наследует взрослую базу и переопределяет только Tier 2/3, а не всё заново). Это даёт «два лица, один скелет»: HTML-структура, отступы, сетка, компоненты — общие; переопределяются только цвет-акцент, шрифт заголовков (Comfortaa/Nunito вместо Bitter/Golos), возможно скругления/декоративные элементы.

**Ключевой принцип из индустрии sub-branding**: субренд либо наследует визуальный язык и голос родителя, либо сознательно отходит от него — но в обоих случаях это должно быть *намеренное архитектурное решение*, а не стихийное расхождение (когда «детская» страница сверстана отдельно и разъезжается по случайным деталям).

### Как применить у нас

Технически: описать общий набор CSS custom properties (Tier 1/2), а «детский регистр» — как *scoped override* этих переменных на уровне контейнера (`.kids-theme { --font-display: 'Comfortaa'; --color-accent: ... }`), а не отдельный набор шаблонов/CSS-файлов с нуля. Это гарантирует, что при обновлении базовой сетки/списков (раздел 1) оба регистра меняются согласованно, а не расходятся. Структурно: **одна и та же типографическая система списка курсов (не-карточная, из раздела 1) должна работать в обоих регистрах** — детский вариант отличается акцентным цветом/шрифтом заголовка и, может быть, более крупными интерактивными зонами (курсы для детей — родители читают с телефона, часто торопливо), но не другой структурой макета. Разные структуры для двух регистров — самый частый провал sub-branding систем (превращается в «два разных сайта»), и именно этого стоит избегать по прямому указанию источника Фроста.

## 6. Айдентика для малых ремесленных/арт-студий

### Источники
- [People of Print — «Care and Process Made Visible»: Rare Ideas' Brand Identity for Handmade Café](https://peopleofprint.com/illustration-2/care-and-process-made-visible-rare-ideas-brand-identity-for-handmade-cafe/) — журнал People of Print — уважаемое издание о графическом дизайне/принте; кейс индийской студии Rare Ideas 2026 года, прямо релевантен (ремесленный бренд общепита с похожей задачей «показать рукотворность без кэмпа»).
- Прочие источники (walkerdesign.co, theindustryleaders.org, afomamarketplace.com) — маркетингово-блоговые, использованы только для извлечения повторяющихся, кросс-источниковых принципов (что снижает риск единичного мнения).

### Извлечённые принципы

**Главный тезис кейса Rare Ideas (лучшая находка этого блока)**: бриф не был «сделать кафе, которое *выглядит* сделанным вручную» — задача была построить систему, в которой забота и процесс *естественным образом видны*. Аутентичность должна идти из **метода/логики системы**, а не быть стилистическим слоем поверх неё. Практически это выразилось в: штампоподобном логотипе с намеренными неровностями края (отсылка к блочной печати и работе с глиной), модульной системе органических форм и текстурных поверхностей, отсылающих к рельефной печати, и **сдержанной, естественной палитре**, которая последовательно, но ненавязчиво проходит через меню/упаковку/вывески/интерьер.

**Общий кросс-источниковый принцип**: материалы должны *реально* соответствовать заявленной руке — например, использовать некрашеную/крафтовую бумагу физически, а не только на экране имитировать её текстуру (см. критику skeuomorphism в разделе 3 — цифровая имитация без физического подтверждения быстро читается как «фальшивая рукотворность»). Визуальная сдержанность (restraint) — то, что удерживает «рустикальность» от скатывания в дилетантство и сохраняет профессиональный вид.

### Как применить у нас

Перенести принцип «аутентичность из метода, а не из стиля» буквально: наш логотип/акцентные графические элементы (если будут) должны иметь настоящую неровность, полученную (или хотя бы правдоподобно смоделированную) из реального процесса — оттиск штампа, мазок кистью, след стека, а не generic «hand-drawn» SVG-brush из библиотеки. Раз в брифе есть реальный преподаватель и реальная студия — прямая рекомендация: **использовать подлинные фотографии процесса (руки, глина, тушь, бумага) как основной источник «рукотворности», а декоративные CSS-эффекты (раздел 3) — оставить строго вспомогательными**, не пытаясь эффектами компенсировать нехватку настоящего визуального материала.

## Топ-5 приёмов к внедрению

**1. Список-этикетка вместо сетки карточек, с единой невидимой модульной сеткой.** (Разделы 1, 2) Заменить блок курсов и «почему мы» на вертикальный/горизонтальный список по музейному принципу: крупный номер/буква + название (Bitter) + короткое описание (Golos Text) + тонкая разделительная линия снизу (не рамка вокруг всего). Иерархия и разница между пунктами достигаются типографикой и позицией (разные размеры модулей под реально разный объём текста каждого курса — раздел 2, максима «одинаковое должно выглядеть одинаково, разное — быть по-настоящему разным»), а не одинаковыми контейнерами. Это прямое и малозатратное решение жалобы клиента, не требует новых визуальных ассетов — только переверстка существующего компонента.

**2. Асимметричная модульная сетка вместо равных колонок.** (Раздел 2) Задать одну строгую 12-колоночную сетку на весь сайт, но сознательно давать разным пунктам списка разную ширину/высоту модуля исходя из их реальной важности и длины реального текста (не lorem ipsum). Верстать «от текста наружу»: сначала посадить финальные русские тексты описаний курсов, потом резать сетку под них — не наоборот.

**3. Верстка и типографская гигиена под кириллицу до релиза.** (Раздел 4) Прогнать все финальные русские тексты (не placeholder) в Bitter/Golos Text, проверить фактическую текстуру строки (кириллица даёт другой ритм и на 15-20% больше объёма, чем латинский эквивалент), при необходимости скорректировать line-height. Внедрить чек-лист Ководства: кавычки-«ёлочки», длинное тире, неразрывные пробелы, защита от переносов-сирот. Дёшево, но напрямую работает на ощущение «сделано с заботой, не на автомате».

**4. Дозированное, функциональное зерно на фонах — не декоративная имитация физической текстуры.** (Раздел 3) Один SVG `feTurbulence`-шум, 4-6% opacity, в тонах палитры (охра/тёмно-зелёный, не серый), только на фоновых плашках/hero, никогда поверх текста. Отказаться от torn-paper/tape/скрапбукинг-эффектов — риск скатиться в кэмп выше пользы. Настоящую рукотворность нести через подлинные фотографии процесса (раздел 6), а не CSS-имитацию бумаги.

**5. Токенная архитектура для регистра «взрослые/дети» с общим скелетом.** (Раздел 5) Один набор CSS custom properties (Tier 1/2/3), детский регистр — scoped override акцентного цвета и шрифта заголовка (Comfortaa/Nunito) поверх той же структурной системы (в т.ч. того же не-карточного списка из приёма №1). Разные структуры макета для двух регистров — самая частая причина, по которой такие системы разваливаются на «два разных сайта»; этого нужно избегать архитектурно с самого начала.

## Против нашего текущего направления

- **Слэб-серифы (Bitter) в кириллице требуют отдельной проверки, а не переноса ощущения с латиницы.** Ни один из найденных источников не осуждает слэб-серифы впрямую, но раздел 4 показывает, что кириллица даёт другую «текстуру» строки (меньше округлых форм, другой ритм) — гарнитура, выбранная по тому, как она смотрится на латинских образцах в каталогах шрифтов, может визуально повести себя иначе на реальном русском тексте. Это не приговор Bitter, а конкретный риск, который нужно закрыть тестом на реальном контенте до релиза (приём №3), а не считать решённым на этапе выбора шрифта.

- **Текстура/материальность — не решает проблему «баналости карточек», и есть риск подменить одну проблему другой.** Источники по skeuomorphism прямо предупреждают: декоративная фактура (бумага, потёртости, скотч) быстро скатывается в «тяжеловесно и аляповато», если не строго функциональна. Клиентская жалоба («банально, шаблонно») — это претензия к *структуре* (сетка карточек), а не к отсутствию фактуры. Если решать проблему добавлением текстуры вместо смены структуры (разделы 1-2), результат рискует остаться «той же сеткой карточек, но с шумом на фоне» — визуально иначе, но структурно так же шаблонно.

- **Broken grid / асимметрия — обоюдоострый инструмент.** Источники о broken grid (раздел 2) сами по себе слабые (маркетинговые блоги), и их энтузиазм по поводу «нарушения сетки ради нарушения» стоит фильтровать через более строгий принцип Vignelli/Баттерика: асимметрия работает, только если она *системна* (нарушает сетку предсказуемо, в одних и тех же логических точках), иначе для бренда, который явно требует ощущения «сделано с заботой», случайная асимметрия прочитается как небрежность, а не как редакционный приём — прямая противоположность цели.

- **Стамп-подобная неровность (как в кейсе Rare Ideas) обязывает к физическому подтверждению.** Если в айдентике появится нарочито «неровный» декоративный элемент (штамп, мазок), источник раздела 6 прямо предупреждает: без реального физического процесса за ним (а не сгенерированного brush-эффекта) это прочитывается как фальшивая рукотворность — риск, обратный тому, чего хочет клиент.

- **Список (list) — не всегда превосходит карточку.** Раздел 1 фиксирует: карточки/визуальный grid браузинг лучше работают, когда изображение — главный носитель информации, а список — когда контент преимущественно текстовый. Если в будущем блок курсов станет более фото-ориентированным (например, витрина готовых работ учеников), чисто типографический список (приём №1) может оказаться не лучшим выбором — нужно реоценить по мере роста количества визуального контента.
