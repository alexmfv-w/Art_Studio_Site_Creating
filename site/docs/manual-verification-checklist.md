## Результаты прохода (2026-08-06)

Проход выполнялся без интерактивного браузера (агент без возможности реального клика/ресайза/скринридера). Ниже — честный статус по каждому пункту: что подтверждено статической проверкой (сборка `npm run build` + разбор сгенерированного `dist/`), а что требует живой браузерной сессии и отмечено как неподтверждённое.

1. **Skip-link (Tab → «Перейти к содержимому» → Enter → фокус на `<main>`).**
   Не проверяемо без реальной браузерной сессии — подтверждена только структурная предпосылка: в `dist/index.html` (и на всех 6 остальных страницах) первый интерактивный элемент в `<body>` — `<a href="#content" class="skip-link">Перейти к содержимому</a>`, целевой элемент `<main id="content" tabindex="-1">` присутствует и имеет `tabindex="-1"` (обязательное условие, чтобы `<main>` мог принять программный фокус через якорь). CSS в `global.css`/собранном `<style>` показывает `.skip-link { position:absolute; top:-100% }` и `.skip-link:focus { top: var(--space-2) }`, то есть ссылка визуально скрыта до фокуса и появляется по `:focus` — это соответствует ожидаемому поведению, но само нажатие Tab/Enter и визуальное появление не наблюдались.

2. **Клавиатурная навигация по ссылкам шапки слева направо.**
   Не проверяемо без реальной браузерной сессии (порядок табуляции — рантайм-поведение). Подтверждена структурная предпосылка: в исходном DOM `dist/index.html` порядок ссылок в `<nav aria-label="Основная" class="nav-desktop">` — Взрослым → Детям → Витрина → Мастер-классы, без `tabindex` или CSS `order`, которые могли бы переставить визуальный/DOM-порядок табуляции. Естественный DOM-порядок при отсутствии `tabindex`/`order` определяет порядок Tab, поэтому проход слева направо ожидаем, но не пронаблюдён вживую.

3. **Мобильное меню мышью (кнопка ☰ видна на ≤768px, клик открывает/закрывает, клик вне — закрывает).**
   Не проверяемо без реальной браузерной сессии (нет возможности реально сузить окно и кликнуть). Подтверждена структурная предпосылка: медиа-запрос `@media (max-width: 768px) { .nav-desktop { display:none } .menu-btn { display:block } }` присутствует в собранном CSS; кнопка использует нативный HTML Invoker Commands API — `<button command="toggle-popover" commandfor="mobile-nav">`, а целевой элемент — `<nav id="mobile-nav" popover ...>`. Открытие/закрытие по клику и закрытие по клику вне попапа (light-dismiss) — встроенное поведение нативного Popover API (`popover` без `popover="manual"` использует auto-режим со light-dismiss), поэтому реализация не требует собственного JS-обработчика клика — в коде компонента (`SiteHeader.astro`) действительно нет такого обработчика. Само визуальное открытие/закрытие не пронаблюдено.

4. **Мобильное меню с клавиатуры (Tab → кнопка ☰ → Enter открывает → Tab по пунктам → Esc закрывает).**
   Не проверяемо без реальной браузерной сессии. Структурно: кнопка `☰` — фокусируемый `<button>`, activation по Enter/Space — стандартное поведение `<button>` при использовании `command`/`commandfor`; закрытие popover по `Esc` — встроенное поведение auto-popover в спецификации Popover API. Полифиллы для обоих API (`invokers-polyfill`, `@oddbird/popover-polyfill`) подключаются условно в `BaseLayout.astro` при отсутствии нативной поддержки (`'commandForElement' in HTMLButtonElement.prototype` / `'popover' in HTMLElement.prototype`), что подтверждено чтением исходника `src/layouts/BaseLayout.astro`. Реальная последовательность нажатий не пронаблюдена.

5. **`aria-expanded` на кнопке ☰ меняется `false → true` при открытии, без своего JS.**
   Не проверяемо без реальной браузерной сессии/DevTools. Подтверждено статически: (а) исходная разметка кнопки не содержит атрибута `aria-expanded` вручную и не содержит `data-*`/скриптовых обработчиков в `SiteHeader.astro`, единственный `<script>` во всём каркасе — условный загрузчик полифиллов в `BaseLayout.astro`, который не трогает `aria-expanded`; (б) синхронизация `aria-expanded` invoker-кнопки с состоянием управляемого popover — задокументированное поведение нативного Invoker Commands API/Popover API (браузер сам выставляет атрибут на элементе-инициаторе). То есть реализация полагается на платформу, как и требует пункт, но фактическое изменение атрибута в панели Elements не пронаблюдено.

6. **Блок «Взрослым/Детям»: две колонки на широком экране, одна колонка на узком (<768px).**
